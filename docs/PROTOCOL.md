# 우르부르 USB 프로토콜

원본 WebToy v1.6.6.0(2001)의 `WebToy.exe`, `uacadll.dll`, `UacaFlt.sys`를 실행하지 않고 분석해 복원했습니다.
LED 출력과 버튼 입력은 실제 기기(macOS)에서 확인했습니다. "추정" 표시가 있는 항목은 아직 확인이 필요합니다.

## 하드웨어

| 항목 | 값 |
|---|---|
| 칩 | Micronas UAC3552A (USB 오디오 코덱) |
| VID / PID | `074D` / `3552` |
| 속도 | USB Full Speed (12 Mbit/s) |
| 인터페이스 | 오디오(표준 클래스) + HID(인터페이스 2) |
| LED | 양쪽 귀. 귀마다 빨강·초록 2색, 출력 4비트 (확인됨) |
| 버튼 | 머리 mute 1개 + 양발 one-click 2개. 입력 3비트 (확인됨) |

오디오는 표준 USB 오디오 클래스라 운영체제 기본 드라이버로 동작합니다.

## 레지스터 접근

원본 드라이버는 사용자 프로그램의 요청을 장치 대상 벤더 컨트롤 전송으로 바꿔 보냅니다.

| 동작 | bmRequestType | bRequest | wValue | wIndex | 데이터 |
|---|---|---|---|---|---|
| 읽기 | `0xC0` | `5` | `0` | 레지스터 주소 | 읽을 바이트 수 |
| 쓰기 | `0x40` | `4` | `0` | 레지스터 주소 | 쓸 바이트 (최대 0x42) |

## 사용하는 레지스터

| 주소 | 방향 | 값 | 의미 |
|---|---|---|---|
| `0xB051` | 쓰기 | `0xF0` | 초기화 1. 상위 4비트를 출력으로 설정 (추정) |
| `0x8087` | 쓰기 | `0xF0` | 초기화 2 (추정) |
| `0xB0A0` | 쓰기 | 1바이트 | LED 출력. 상위 4비트 사용 |
| `0xB0A2` | 읽기 | 1바이트 | 버튼 입력. 하위 3비트 사용 |

## LED 비트 (확인됨)

| 비트 | 값 | LED |
|---|---|---|
| 7 | `0x80` | 왼쪽 귀 빨강 |
| 6 | `0x40` | 왼쪽 귀 초록 |
| 5 | `0x20` | 오른쪽 귀 빨강 |
| 4 | `0x10` | 오른쪽 귀 초록 |

귀마다 다리 두 개짜리 2색 LED가 들어 있는 것으로 보입니다. 같은 귀의 빨강·초록 비트를 함께 켜면(`0xC0`, `0x30`)
그 귀는 꺼지므로 노랑은 만들 수 없습니다. 빨강은 빠르게 깜빡이면 주황빛으로 보입니다.

macOS에서 원본 드라이버 없이 libusb 벤더 컨트롤 전송으로 초기화와 출력이 동작했습니다.

## LED 패턴

원본은 (출력값, 지속시간 × 0.1초) 쌍의 목록을 순서대로 재생했습니다. 서버가 보낸 명령 문자에 따라 내장 패턴을 골랐습니다.

| 명령 | 패턴 | 해석 (추정) |
|---|---|---|
| `L` | `80 05 40 05` | 왼쪽 귀 빨강 ↔ 초록 |
| `R` | `10 05 20 05` | 오른쪽 귀 초록 ↔ 빨강 |
| `B` | `90 05 60 05` | 왼빨+오초 ↔ 왼초+오빨 (엇갈려 교대) |
| 시험 | `80 01 40 01 C0 01 10 01 20 01 30 01` | 비트 순회 |

## 버튼 (확인됨)

| 비트 | 값 | 버튼 |
|---|---|---|
| 0 | `0x01` | 오른발 |
| 1 | `0x02` | 왼발 |
| 2 | `0x04` | 머리 (mute) |

누르면 비트가 1이 됩니다. 원본은 `0xB0A2`를 주기적으로 읽어 눌림 횟수를 세는 방식으로 채터링을 걸렀고,
이 프로그램은 시작 시점의 값을 "안 누른 상태"로 삼아 극성과 무관하게 동작합니다.

## 확인이 필요한 것

- Windows 11에서 WinUSB로 같은 전송이 통과하는지
- 초기화 값 두 개의 정확한 의미
