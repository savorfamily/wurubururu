# 우르부르 USB 프로토콜

원본 WebToy v1.6.6.0(2001)의 `WebToy.exe`, `uacadll.dll`, `UacaFlt.sys`를 실행하지 않고 분석해 복원했습니다.
**실제 기기 검증 전**이며, "추정" 표시가 있는 항목은 확인이 필요합니다.

## 하드웨어

| 항목 | 값 |
|---|---|
| 칩 | Micronas UAC3552A (USB 오디오 코덱) |
| VID / PID | `074D` / `3552` |
| 속도 | USB Full Speed (12 Mbit/s) |
| 인터페이스 | 오디오(표준 클래스) + HID(인터페이스 2) |
| LED | 양쪽 귀. 출력 4비트 (귀마다 2색으로 추정) |
| 버튼 | 머리 mute 1개 + 양발 one-click 2개. 입력 3비트 |

오디오는 표준 USB 오디오 클래스라 운영체제 기본 드라이버로 동작합니다.

## 레지스터 접근

원본 드라이버는 사용자 프로그램의 요청을 장치 대상 벤더 컨트롤 전송으로 바꿔 보냅니다.

| 동작 | bmRequestType | bRequest | wValue | wIndex | 데이터 |
|---|---|---|---|---|---|
| 읽기 | `0xC0` | `5` | `0` | 레지스터 주소 | 읽을 바이트 수 |
| 쓰기 | `0x40` | `4` | `0` | 레지스터 주소 | 쓸 바이트 (최대 0x42) |

## 사용하는 레지스터

| 주소 | 방향 | 값 | 의미 |
|---|---|---|---|
| `0xB051` | 쓰기 | `0xF0` | 초기화 1. 상위 4비트를 출력으로 설정 (추정) |
| `0x8087` | 쓰기 | `0xF0` | 초기화 2 (추정) |
| `0xB0A0` | 쓰기 | 1바이트 | LED 출력. 상위 4비트 사용 |
| `0xB0A2` | 읽기 | 1바이트 | 버튼 입력. 하위 3비트 사용 |

## LED 패턴

원본은 (출력값, 지속시간 × 0.1초) 쌍의 목록을 순서대로 재생했습니다. 서버가 보낸 명령 문자에 따라 내장 패턴을 골랐습니다.

| 명령 | 패턴 | 해석 (추정) |
|---|---|---|
| `L` | `80 05 40 05` | 왼쪽 귀 두 색 교대 |
| `R` | `10 05 20 05` | 오른쪽 귀 두 색 교대 |
| `B` | `90 05 60 05` | 양쪽 귀 동시 교대 |
| 시험 | `80 01 40 01 C0 01 10 01 20 01 30 01` | 비트 순회 |

## 버튼

원본은 `0xB0A2`를 주기적으로 읽어 bit0, bit1, bit2의 눌림 횟수를 세는 방식으로 채터링을 걸렀습니다.
눌렀을 때 비트가 1이 되는지 0이 되는지는 확인되지 않아, 이 프로그램은 시작 시점의 값을 "안 누른 상태"로 삼습니다.

## 확인이 필요한 것

- 각 출력 비트가 어느 귀의 어느 색인지 (`wuruburu leds`)
- 각 입력 비트가 어느 버튼인지, 눌림 극성 (`wuruburu buttons`)
- macOS에서 오디오·HID 드라이버가 붙은 상태로 벤더 컨트롤 전송이 통과하는지
- 초기화 값 두 개의 정확한 의미
